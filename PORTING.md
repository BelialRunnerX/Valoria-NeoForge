# Valoria — Forge 1.20.1 → NeoForge 1.21.1 porting log

Target: NeoForge 21.1.251, Minecraft 1.21.1, Java 21, Gradle 8.14.5, ModDevGradle 2.0.147, Parchment 2024.11.17.
Depends on the Tridot 1.21.1 port (`pro.komaru:Tridot:1.21.1-1.0.169`, mavenLocal).

Every non-trivial rewrite is listed here; code sites carry a matching `// PORT NOTE:` comment (449 sites in 323 of 749 Java files).
Items under **Unverified at runtime** compile but could not be exercised without launching the game.
Items under **Config behaviour changes** are options whose effect may differ from 1.20.1.

Status (2026-09-23): **working build, not fully validated** — client starts, creates/loads worlds, basic play works, dedicated server boots clean; gameplay systems still need play-testing (see KNOWN_ISSUES.md). Build status: `gradlew.bat build` passes (artifact `build/libs/Valoria-1.21.1-1.0.4.2.jar`) and `gradlew.bat runData` boots the full mod set (NeoForge, Tridot, Curios, GeckoLib, JEI, Jade, JER, KubeJS, Dummmmmmy/Moonlight) through registration and regenerates `src/generated/resources` (3.7k files; identical set to the 1.20.1 output apart from `music_discs.json` and the new tier/enchantable/wolf_food/dyeable tags). Launch with `gradlew.bat runClient`.

Runtime problems found and fixed while booting datagen (all documented in the phase tables): Attribute holder cast in `AttributeMixin`, NeoForge event-bus strictness (no-listener `register`, static handlers, abstract `InputEvent`), items resolving particle holders eagerly, wrong-loader jars from Modrinth (Moonlight, JER), missing JitPack repository for KubeJS.

## Nature of the changes — how to read this document and the code comments

Converting to NeoForge 1.21.1 required three kinds of change. Every `// PORT NOTE:` comment in the code is prefixed accordingly, and the tables below use the same wording:

| Marker | Meaning | Where it applies |
|---|---|---|
| `PORT NOTE:` (no qualifier) | **Mechanical API translation.** Same behaviour as 1.20.1; only the API the code talks to changed (Forge → NeoForge class/method renames, NBT → data components, `RegistryObject` → `DeferredHolder`, new event names, new rendering calls, 1.21 JSON formats). This is the overwhelming majority of the 449 sites. | Everywhere |
| `PORT NOTE (behaviour change …):` | **Runtime behaviour differs from 1.20.1.** Either the platform offers no equivalent (feature not available), the platform forced a different timing, or a tolerance had to be added. Each one is also listed in KNOWN_ISSUES.md → "Changed behaviour". | `LegacyIdRemap` / `Events.onMissingMappings` (no `MissingMappingsEvent`), `Events` FillBucket handler (no event), `Events.onLivingHurt` and Tridot percent armour (`LivingIncomingDamageEvent` timing), `CapabilityEvents.onServerTick` and Tridot `Events.onServerTick` (previously dead static handlers are now live), `ValoriaAttachments` (also copied on non-death clones), `AbilityRegistry.register` (idempotent), data-pack fixes to upstream typos that 1.20.1 turned into air |
| `PORT NOTE (upstream bug fix):` | **A latent bug of the original code was fixed** because 1.21 or the now-active handlers exposed it. | `OnDungeonVisitListener.isPlayerInStructure`, Tridot `MusicModifier.DungeonMusic` (bounding box of an invalid structure start) |
| `PORT NOTE (API change …):` | **Tridot's public API differs for dependent mods** (Tridot repository only). | enchantable tags instead of `EnchantmentCategory`, side-loaded model keys, `addCustomModel`, `getBowModels`/`getCrossbowModels`, loot target aliases |
| `PORT NOTE (port metadata - deliberate redirect):` | **Not a platform change**: repository/URL metadata deliberately points at the port instead of the original author. | `neoforge.mods.toml`, `ClientEvents` update link, `update.json`, issue templates, `CONTRIBUTING.md` |

Things that did **not** change: gameplay values (damage, durations, costs, weights), item/block/entity ids, config keys and defaults, loot table contents (apart from the format conversion and the two documented summon-book entries), recipes (apart from format and two typo fixes), textures, models, sounds, structures and worldgen parameters.

## Phase 6 — capabilities → data attachments, events

| Change | Detail |
|---|---|
| Attachments | Forge capabilities (`pages`, `nihility_level`, `magma_level`, `ability_tracker`) → `ValoriaAttachments` (`AttachmentType.serializable(...).copyOnDeath()` on `NeoForgeRegistries.ATTACHMENT_TYPES`, same ids and NBT layout). Providers implement `INBTSerializable<CompoundTag>` with `HolderLookup.Provider` signatures; `LazyOptional` is gone. `INihilityLevel/IMagmaLevel/IUnlockable.of(Entity)` and `PlayerAbilityProvider.of(Entity)` return `Optional`s (players only). `CapabilityEvents`: attach handler removed, `onClone` keeps `copyFrom` + sync packets, `PlayerTickEvent.Post`, `ServerTickEvent.Post`, advancements via `server.getAdvancements().get(loc)`. |
| Event bus registration | NeoForge's bus throws when an object without instance `@SubscribeEvent` methods is registered (Forge silently ignored it). `forgeBus.register(this)` was removed from `Valoria` (all its handlers are static mod-bus listeners in `RegistryEvents`) and from Tridot's entrypoint (fixed in the Tridot port, republished as 1.21.1-1.0.169). NeoForge also refuses `static` `@SubscribeEvent` methods on instance-registered objects. `Events.onTooltip` is registered via `addListener(Events::onTooltip)` (client) as before — only its inert annotation was dropped, behaviour unchanged. `CapabilityEvents.onServerTick` (dungeon-visit codex unlock check) and Tridot's `Events.onServerTick` (dungeon music packets) were `static` in 1.20.1 with no other registration — Forge skipped them silently, so **they never ran in 1.20.1**. They are now instance methods and therefore active; remove their `@SubscribeEvent` to restore the old (dead) behaviour. Likewise the bus rejects listeners on abstract event classes: `KeyBindHandler.onInput(InputEvent)` is now registered once per concrete `InputEvent` subclass (`KeyBindHandler.register`), and the no-op `@EventBusSubscriber` on `ItemTabRegistry` (no handlers; `addCreative` is wired via `addListener`) was removed. |
| Missing mappings | `MissingMappingsEvent` does not exist in NeoForge. The old remap table is preserved in `core/LegacyIdRemap.java` (`remapBlock/remapItem`) but is **not wired**; renamed ids from pre-1.0.4 worlds are not remapped (see Unverified). |
| Damage events | `LivingAttackEvent`/`LivingHurtEvent` → `LivingIncomingDamageEvent` (`Events.onLivingAttack`, `Events.onLivingHurt`, `priority = HIGH`); nihility damage uses `getAttribute(type.damageAttr())` and `attackAttr.getAttribute().is(AttributeReg.NIHILITY_DAMAGE.getKey())`. |
| Other events | `ItemEntityPickupEvent.Pre.setCanPickup(TriState.FALSE)`; `MobEffectEvent.Applicable.setResult(Result.DO_NOT_APPLY)`; `isCancelable()` removed (`event instanceof ICancellableEvent`); `FillBucketEvent` handler removed (no equivalent; see Unverified); `syncCrusherRecipes` uses `RecipeHolder` + `reloadableRegistries`. `Blocks`/`DamageTypes` fully qualified where `net.neoforged.neoforge.common.Tags` clashed. |

## Automated in-game harness

`tools/porttest/porttest.js` (KubeJS server script, run through the `clientAuto` gradle run configuration) exercises the ported systems in a real world without any input device: portal formation and travel both ways, kiln recipe execution, enchantment availability/exclusivity, Curios attribute application through the right-click and API paths, nihility damage, dispenser arrows, jukebox playback, painting variants, spawning of every living entity, four boss fights with player-credited kills and loot, crypt generation and the dungeon-visit codex unlock. Its README lists the checks and the pitfalls found while writing it (dead singleplayer host saved in `level.dat`, furnace NBT without `CookTimeTotal`, `/place structure` not registering starts, Rhino overload ambiguity). KNOWN_ISSUES.md keeps the current verified / unverified split; the list below is the original test backlog and several entries have since passed.

## Unverified at runtime (original backlog)

- **Portal**: `Portal`/`DimensionTransition` flow (`ValoriaPortalBlock`, `ValoriaTeleporter`) — portal search radius, spawn placement and cooldown reproduce the 1.20.1 `ITeleporter` logic. *Verified by the harness 2026-09-24:* ring formation, Overworld → Valoria, return portal generation, trip back.
- **Attachments**: `copyOnDeath()` copies pages/nihility/magma/abilities on death; NeoForge also copies attachments on other clones (end return), where 1.20.1 recreated them — behaviour is a superset. Old-world capability NBT is read through the same keys but has not been loaded from a real 1.20.1 save.
- **Legacy id remap**: `LegacyIdRemap` is not wired (no `MissingMappingsEvent`). Worlds still containing pre-rename block/item ids will lose those blocks/items.
- **Damage pipeline**: `LivingIncomingDamageEvent` fires before armour/absorption like `LivingAttackEvent`, but the former `LivingHurtEvent` handler now also runs at that point (priority HIGH). Nihility damage scaling and damage indicators should be checked against 1.20.1 numbers.
- **Bucket handling**: the `FillBucketEvent` handler (Valoria fluid/bucket interaction) has no NeoForge equivalent and was removed; check bucket use on Valoria fluids/blocks.
- **Item NBT migration**: data components + `custom_data` fallbacks. Items from 1.20.1 saves rely on vanilla DFU moving root NBT into `minecraft:custom_data`; verify soul collectors, magma sword charge, summon books, poisoned weapons, rotten food.
- **Enchantments as data**: Bleeding/Accuracy/Explosive Flame availability in the enchanting table & anvil, Bleeding proc rate, Explosive Flame exclusivity with Fire Aspect, enchantment book loot.
- **Loot conversions**: `enchant_with_levels` default option set (`on_random_loot`) is close to but not identical with the old `treasure: true` pool; summon-book components in crypt/monstrosity chests.
- **Entity dimensions**: eye heights / riding offsets moved to type builders — check mounted mobs (scavenger riders, king crab) and projectile aim of draugr/necromancer.
- **KubeJS**: schema rewrite for 2101 (script-facing keys unchanged: `ingredient(s)`, `result/output`, `time`, `experience`, `cookingtime`, `loot_table`, `core/cores`, `category`).
- **Jade / JER / JEI**: tool-tier tooltip, mob/chest loot pages, kiln/workbench/alchemy/crusher categories with stamped ids.
- **HUD layers**: nihility bar/shield, magma bar, soul bar, ability overlay ordering relative to vanilla layers (`RenderGuiLayerEvent.Post` + `VanillaGuiLayers`).
- **Supporter cloaks**: `getSkin()` mixin — capes and elytra fallback for listed names; `PatreonRewards` config.
- **Dispenser behaviours** for Valoria throwables (rewritten on `DefaultDispenseItemBehavior`).
- **Music disc** via `jukebox_playable` (jukebox playback, comparator output, creative tab).
- **Strippable logs** via the `neoforge:strippables` data map.
- **Painting variants** as datapack entries (placement sizes, creative tab entries).
- **Mixins** (targets exist in 1.21.1 sources, but injection points are only validated when the game boots): max-health cap 100000, glow-face skip rendering, supporter capes, Valoria sky colour.

- **Newly active handlers**: `CapabilityEvents.onServerTick` and Tridot `Events.onServerTick` never ran in 1.20.1 (static methods on instance registration). Check that the dungeon-visit codex unlock and the dungeon music packets behave sensibly; each can be disabled by removing its `@SubscribeEvent`.
