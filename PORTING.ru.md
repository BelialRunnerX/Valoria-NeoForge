# Valoria — журнал портирования с Forge 1.20.1 на NeoForge 1.21.1

> 🇬🇧 Основная версия — [PORTING.md](PORTING.md) (английский). Перевод сделан в знак уважения к автору оригинала и может отставать; при расхождениях верна английская версия.

Цель: NeoForge 21.1.251, Minecraft 1.21.1, Java 21, Gradle 8.14.5, ModDevGradle 2.0.147, Parchment 2024.11.17.
Зависит от порта Tridot 1.21.1 (`pro.komaru:Tridot:1.21.1-1.0.169`, mavenLocal).

Здесь перечислены все нетривиальные переработки; места в коде помечены комментарием `// PORT NOTE:` (449 мест в 323 из 749 Java-файлов).
Пункты раздела **Не проверено в рантайме** компилируются, но не могли быть опробованы без запуска игры.
Пункты раздела **Изменения поведения конфигурации** — опции, чей эффект может отличаться от 1.20.1.

Состояние (2026-09-23): **рабочая сборка, не полностью проверенная** — клиент запускается, создаёт/загружает миры, базовая игра работает, выделенный сервер запускается с чистым логом; игровые системы ещё требуют тестирования (см. KNOWN_ISSUES.ru.md). `gradlew.bat build` проходит (артефакт `build/libs/Valoria-1.21.1-1.0.4.2.jar`), а `gradlew.bat runData` загружает полный набор модов (NeoForge, Tridot, Curios, GeckoLib, JEI, Jade, JER, KubeJS, Dummmmmmy/Moonlight) до регистрации включительно и перегенерирует `src/generated/resources` (3,7 тыс. файлов; тот же набор, что и вывод 1.20.1, кроме `music_discs.json` и новых тегов уровней/enchantable/wolf_food/dyeable). Запуск: `gradlew.bat runClient`.

Проблемы рантайма, найденные и исправленные при запуске datagen (все описаны в таблицах фаз): приведение holder-а атрибута в `AttributeMixin`, строгость шины событий NeoForge (`register` без слушателей, статические обработчики, абстрактный `InputEvent`), предметы, слишком рано разрешавшие holder-ы частиц, jar-файлы не того загрузчика с Modrinth (Moonlight, JER), отсутствующий репозиторий JitPack для KubeJS.

## Характер изменений — как читать этот документ и комментарии в коде

Переход на NeoForge 1.21.1 потребовал изменений трёх видов. Каждый комментарий `// PORT NOTE:` в коде снабжён соответствующей пометкой, и таблицы ниже используют те же формулировки:

| Пометка | Значение | Где встречается |
|---|---|---|
| `PORT NOTE:` (без уточнения) | **Механический перевод API.** Поведение такое же, как в 1.20.1; изменился только API, с которым работает код (переименования классов/методов Forge → NeoForge, NBT → компоненты данных, `RegistryObject` → `DeferredHolder`, новые имена событий, новые вызовы рендера, форматы JSON 1.21). Это подавляющее большинство из 449 мест. | Везде |
| `PORT NOTE (behaviour change …):` | **Поведение в рантайме отличается от 1.20.1.** Либо у платформы нет аналога (возможность недоступна), либо платформа навязала другой момент срабатывания, либо пришлось добавить устойчивость к повторам. Каждый такой пункт также перечислен в KNOWN_ISSUES.ru.md → «Изменённое поведение». | `LegacyIdRemap` / `Events.onMissingMappings` (нет `MissingMappingsEvent`), обработчик FillBucket в `Events` (нет события), `Events.onLivingHurt` и процентная броня Tridot (момент `LivingIncomingDamageEvent`), `CapabilityEvents.onServerTick` и `Events.onServerTick` в Tridot (ранее мёртвые статические обработчики теперь работают), `ValoriaAttachments` (копируются и при клонировании не через смерть), `AbilityRegistry.register` (идемпотентен), исправления опечаток оригинала в датапаке, которые 1.20.1 превращал в воздух |
| `PORT NOTE (upstream bug fix):` | **Исправлена скрытая ошибка оригинального кода**, которую проявили 1.21 или ставшие активными обработчики. | `OnDungeonVisitListener.isPlayerInStructure`, `MusicModifier.DungeonMusic` в Tridot (bounding box невалидного старта структуры) |
| `PORT NOTE (API change …):` | **Публичный API Tridot отличается для зависимых модов** (только репозиторий Tridot). | теги enchantable вместо `EnchantmentCategory`, ключи подгружаемых моделей, `addCustomModel`, `getBowModels`/`getCrossbowModels`, синонимы целей лута |
| `PORT NOTE (port metadata - deliberate redirect):` | **Не изменение платформы**: метаданные репозитория/URL намеренно указывают на порт, а не на автора оригинала. | `neoforge.mods.toml`, ссылка на обновление в `ClientEvents`, `update.json`, шаблоны issue, `CONTRIBUTING.md` |

Что **не** менялось: игровые значения (урон, длительности, стоимости, веса), идентификаторы предметов/блоков/сущностей, ключи конфигурации и значения по умолчанию, содержимое таблиц лута (кроме конвертации формата и двух задокументированных записей книг призыва), рецепты (кроме формата и двух исправленных опечаток), текстуры, модели, звуки, структуры и параметры генерации мира.

## Фаза 2 — предметы, NBT предметов → компоненты данных, инструменты, броня

| Изменение | Подробности |
|---|---|
| NBT предметов | NBT у ItemStack больше нет. Каждое значение стака (`Souls`, `charge`, `usageCount`, `poison_hits`, `ValoriaRot`, `OriginalItem`, `IsNightActive`, `IsDarkActive`, `EyeState`, `ToggleState`, `isVisible`/`isPlayed`, `DisplayColor`) — зарегистрированный компонент данных `valoria:*` (`DataComponentsRegistry`). Чтение откатывается на `minecraft:custom_data`, поэтому предметы из миров 1.20.1 (DFU переносит корневой NBT туда) сохраняют значения. `EntityTag` у книг призыва — ванильный компонент `minecraft:entity_data`. |
| Еда / гниение | `FoodProperties` — компонент (`has(DataComponents.FOOD)`); `.meat()` исчез → тег предметов `minecraft:wolf_food` из datagen. `DyeableLeatherItem` → тег `minecraft:dyeable` + `DyedItemColor`. |
| Инструменты / оружие | `Tier` → `SimpleTier`; модификаторы атрибутов строятся через `ItemAttributeModifiers` с идентификаторами `ResourceLocation`; `getAttributeModifiers(slot, stack)` → `getDefaultAttributeModifiers(stack)`; `hurtAndBreak(amount, entity, slot)` / `hurtAndBreak(amount, ServerLevel, ServerPlayer, Consumer<Item>)` для curios (`IBreakableCurio.accessoryHurt`). `SpectralBladeItem` использует `SoundEvents.SOUL_ESCAPE.value()`; исправлены импорты `ScytheItem`/`BandageItem`. |
| Броня GeckoLib | Контроллеры анимации `SamuraiArmorItem`/`SpiderArmor` читают `LivingEntity#getArmorSlots()` у сущности из состояния анимации вместо удалённой раскладки `getData(DataTickets.EQUIPMENT_BY_SLOT)`. |
| Опыт с руды | `WickedOreBlock.getExpDrop(state, level, random, pos, fortune, silkTouch)` → `getExpDrop(state, level, pos, blockEntity, breaker, tool)`, возвращает `xpRange.sample(level.getRandom())`; Silk Touch обрабатывает `processBlockExperience` NeoForge. |
| Предметы с частицами | NeoForge вызывает `RegisterEvent` предметов раньше `particle_type`, поэтому `ParticleRegistry.SPHERE.get()` внутри поставщиков предметов бросал «Trying to access unbound value» при загрузке. `ParticleMaterialItem`, `CoreItem`, `UnstableCore` теперь хранят `Supplier<? extends ParticleType<?>>` (`DeferredHolder`), разрешаемый при использовании (`getParticle()`); конструкторы с `ParticleType` оставлены как делегаты. 13 мест вызова в `ItemsRegistry` передают holder. |
| Скины / модели | `SkinsRegistry` использует `DeferredHolder<Item, ? extends Item>` и `Map<ModelResourceLocation, BakedModel>`; `ModelResourceLocation.standalone/inventory`. |

| Карты | Holder-ы `MapDecorationTypes.RED_X` / `BLACK_BANNER`; `TreasureMapItemListing` из Tridot принимает `Holder<MapDecorationType>`. |

## Не проверено в рантайме

- **Портал**: путь `Portal`/`DimensionTransition` (`ValoriaPortalBlock`, `ValoriaTeleporter`) — радиус поиска портала, размещение появления и перезарядка воспроизводят логику `ITeleporter` 1.20.1, но лишь компилировались. Проверьте путешествие Верхний мир ⇄ Valoria в обе стороны и повторное использование портала.
- **Attachments**: `copyOnDeath()` копирует страницы/Нихилити/магму/способности при смерти; NeoForge копирует attachments и при других клонированиях (возвращение из Края), где 1.20.1 создавал их заново — поведение является надмножеством. NBT capabilities старых миров читается по тем же ключам, но с реального сохранения 1.20.1 не загружался.
- **Перемаппинг устаревших идентификаторов**: `LegacyIdRemap` не подключён (нет `MissingMappingsEvent`). Миры, содержащие идентификаторы блоков/предметов до переименования, потеряют эти блоки/предметы.
- **Конвейер урона**: `LivingIncomingDamageEvent` срабатывает до брони/поглощения, как `LivingAttackEvent`, но бывший обработчик `LivingHurtEvent` теперь тоже выполняется в этой точке (приоритет HIGH). Масштабирование урона Нихилити и индикаторы урона стоит сверить с числами 1.20.1.
- **Вёдра**: обработчик `FillBucketEvent` (взаимодействие с жидкостями/вёдрами Valoria) не имеет аналога в NeoForge и удалён; проверьте использование вёдер на жидкостях/блоках Valoria.
- **Миграция NBT предметов**: компоненты данных + откат на `custom_data`. Предметы из сохранений 1.20.1 полагаются на перенос корневого NBT ванильным DFU в `minecraft:custom_data`; проверьте коллекторы душ, заряд магмового меча, книги призыва, отравленное оружие, гнилую еду.
- **Зачарования как данные**: доступность Bleeding/Accuracy/Explosive Flame в столе зачарований и наковальне, шанс срабатывания Bleeding, взаимоисключение Explosive Flame с Fire Aspect, лут книг зачарований.
- **Конверсии лута**: набор опций по умолчанию `enchant_with_levels` (`on_random_loot`) близок, но не идентичен старому пулу `treasure: true`; компоненты книг призыва в сундуках крипт/монстрозностей.
- **Размеры сущностей**: высота глаз / смещения верховой езды перенесены в билдеры типов — проверьте всадников (наездники scavenger, king crab) и прицеливание снарядов draugr/necromancer.
- **KubeJS**: переписанные схемы для 2101 (ключи для скриптов не изменились: `ingredient(s)`, `result/output`, `time`, `experience`, `cookingtime`, `loot_table`, `core/cores`, `category`).
- **Jade / JER / JEI**: подсказка уровня инструмента, страницы лута мобов/сундуков, категории печи/верстака/алхимии/дробилки с проставленными идентификаторами.
- **Слои HUD**: полоска/щит Нихилити, полоска магмы, полоска душ, порядок оверлея способностей относительно ванильных слоёв (`RenderGuiLayerEvent.Post` + `VanillaGuiLayers`).
- **Плащи спонсоров**: миксин `getSkin()` — плащи и запасной вариант для элитр у перечисленных имён; опция `PatreonRewards`.
- **Поведение раздатчиков** для метательных предметов Valoria (переписано на `DefaultDispenseItemBehavior`).
- **Музыкальный диск** через `jukebox_playable` (воспроизведение, выход компаратора, вкладка творчества).
- **Очищаемые брёвна** через data map `neoforge:strippables`.
- **Варианты картин** как записи датапака (размеры размещения, записи вкладки творчества).
- **Миксины** (цели существуют в исходниках 1.21.1, но точки внедрения проверяются только при запуске игры): потолок максимального здоровья 100000, пропуск рендера светящихся граней, плащи спонсоров, цвет неба Valoria.
- **Материалы Tetra** неактивны (нет Tetra для 1.21).
- **Вновь активные обработчики**: `CapabilityEvents.onServerTick` и `Events.onServerTick` в Tridot в 1.20.1 никогда не выполнялись (статические методы при регистрации экземпляра). Проверьте, что разблокировка кодекса при посещении данжа и пакеты музыки данжей ведут себя разумно; каждый можно отключить, убрав его `@SubscribeEvent`.

## Изменения поведения конфигурации

| Опция | Примечание |
|---|---|
| `server.gameplay.maxNihilityAction` (TELEPORT) | Телепорт теперь использует `ServerPlayer.findRespawnPositionAndUseSpawnBlock(true, …)`, который, как настоящее возрождение, расходует якоря возрождения. |
